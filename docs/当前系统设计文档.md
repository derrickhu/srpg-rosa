## 一、整体结构：局外 Meta + 局内 Run

两层状态（`src/game/state/GameState.ts`）：

- **MetaState（持久，存档 `srpg_meta_v3`）**：角色名册（等级/已学技能/装配技能）、魂晶、副本解锁/通关记录、每日扫荡配额消耗、各章已领星 `chapterStarsByDungeonId`（不升档）。
- **RunState（单局临时，存档 `srpg_run_v3` 断点续局）**：节点进度、局内金币、地形券、药剂、**按角色记的纹章 `skillMods`**、**临时技能槽 `runTempSkill`**、三选一待选战利品、本局评星累计 `starStats`。

流程：

```
Home → 大厅 Shell（底部 Tab）→ 冒险页选章节出发
  → Run：节点序列 [战斗节点: 布阵→战斗→三选一] / [商店节点]
  → Boss 通关 → 魂晶结算回大厅

副本页「无尽试炼」：
  → 布阵一次 → 同图按波刷怪（最多 10 波）
  → 清波 → 魂晶 + 技能三选一 → 随机落点刷下一波
  → 全灭或打完 10 波 → 回副本页，记下最高波
```

## 二、元素产出-消耗环（固化设计）

每类元素**只有一个清晰的获取场景和一个清晰的使用场景**：

| 元素 | 产出 | 消耗 | 归属 | 实现 |
|---|---|---|---|---|
| **魂晶** | **节点首通**当场入账（普通 +2 / Boss +5）；**整章三星**每星第一次点亮发对应魂晶（三星之和 = `metaReward`）；重复通关 / 扫荡另给 `DUNGEON_REPEAT_SOUL` | 角色升级、学技能、解锁角色/副本 | 局外 | `ProgressManager.applyVictory` / `finishRunVictory` |
| **金币** | 战斗击杀当场掉落，总额仍是本关 `goldReward`，飞入左上金币栏 | 仅商店节点消费 | 局内 | `RunState.gold` |
| **纹章** | 战斗胜利后**三选一**（主要来源） | 挂在**那个角色**身上、只强化他的**主技能**，生效到本局结束 | 局内构筑主线 | `skillModCatalog` / `RunState.skillMods` |
| **药剂** | 商店节点购买、三选一凑不满时兜底 | **战斗中手动点击使用**（群疗/攻击增益/减速敌方） | 局内 | `potionCatalog` / `BattleSim.usePotion` |
| **地形券** | 商店节点购买（高地/森林/城墙 3 种） | 布阵时放置改地形 | 局内 | `RunState.terrainCharges`（按类型计数） |
| **主技能** | 局外魂晶学习（永久进池，**限本角色路线内**），布阵页可在已学技能间切换 | 战斗中释放（玩家点目标 / 托管时由 AI 放） | 局外 | `MetaManager.learnSkill` / `RunState.runEquip` |
| **临时技能** | 局内商店购买，**场景专属、不挑职业** | 第二技能位，与主技能共用每回合一次的施放额度 | 局内 | `ShopManager` / `RunState.runTempSkill` |

商店节点商品收敛为**三类**：药剂、地形券、场景专属临时技能（`DungeonDef.roguelikePool` 按章节配池，`ShopManager.rollShop` 每次抽 3，有药剂就保底 1 件）。

### 魂晶：按首通发放

同一个节点的首通奖励**只发一次**（用 `meta.clearedNodesByDungeonId` 判定），所以重复刷老节点
拿不到永久货币，「进副本赢两关就跑」这条路自然不成立。因此魂晶可以当场入账、当场显示 `+2`，
不需要「暂存 / 通关兑现」这类概念。放弃副本不扣任何东西，丢的只是局内物资。

反刷是**测试守着的性质**，不是靠人肉复查：`src/game/state/__tests__/economy.test.ts`
里「赢两场就跑重复十次，魂晶不得增长」。

整章另有三星评价（`DungeonDef.stars`）：第 1 星永远是成功通关，后两星按章配置
（回合上限 / 伤亡 / 不用药 / 不买补给）。每颗星的魂晶只领一次，扫荡不评星、只发本关重复奖。
冒险页章节卡分「本关奖励」和「通关奖励」两栏。

已全部首通的章节，冒险页开始按钮上方会写明今日扫荡次数——
两次进副本的界面长得一样，不写玩家只能打完才发现没涨。

### 战后结算

中途胜利不再弹「胜利 + 奖励」：金币已在击杀时飞进栏里，直接出纹章三选一。
只有**当前场景通关**才出胜利面板，并且只展示本次入账的魂精。

三选一屏：挑一枚纹章（`ProgressManager.rollLoot`），按稀有度描边。
卡面自上而下是**头像（给谁）→ 技能图标（哪一招）→ 纹章名 + 类型小标签（加什么）**，
纹章图标只当 16px 角标；专属纹章在色条上标「专属纹章 · 稀有」，
因为它换个技能就再也拿不到。`claimLoot` 或 `skipLoot` 后推进节点。

两屏都是 `pushOverlay` 压在战场上，不替换场景——玩家看得见自己刚打完的那张图。
品类刻意不重叠：第一屏发货币，第二屏挑强化。

### 纹章

玩家看到的名字是**纹章**（游戏名「无尽纹章」的局内构筑物）。代码和存档仍叫 `skillMods`。
纹章是 `SkillSpec → SkillSpec` 的纯函数（`src/data/skillModCatalog.ts`），
结算前由 `effectiveSkillSpec` 套一层，战斗逻辑本身不感知它的存在。

**它在三层成长里的位置**：玩家改变一个角色打法的手段有三个，各管一块不重叠的事，
这样每拿到一个东西都能预期它会改变什么、不会改变什么。

| 层 | 允许改 | 不许改 | 怎么拿到 |
|---|---|---|---|
| 可学技能（主槽） | 距离、形状、范围、目标个数、冷却、附加被动、特效 | **定位**（必须等于角色路线） | 局外魂晶解锁，布阵页免费切换 |
| **词条** | 数值、范围扩大、附加效果 | **基础形状和可打范围**（那是原技能的身份） | 局内战斗胜利三选一 |
| 临时技能（第二槽） | 跨定位——输出角色可以带治疗 | 不吃词条 | 局内商店买 |

三层重合的部分就是策略空间：某个数值或范围不够用时，升级技能、赌词条、
买临时技能三条路都通，选哪条是玩法。

词条这一层「不许改基础形状」的界线：**扩大**可以（「横扫」把邻格环摊成整片圆盘，
原来打得到的照样打得到），**换打法**不行（单体变群体会抹掉「点谁」这个决策，
而那是单体技能的全部取舍所在——同一条原则见下文 `splashRatio`）。
例外是**专属**词条的质变（「蔓延」把破甲咒摊成 2 格群体）：它只对一招开放、
rare 起步，玩家拿到时预期的就是「这一招换个用法」。

**两层结构**：

| | 数量 | 出现条件 | 叠层 | 定位 |
|---|---:|---|---|---|
| **普通词条** `scope.kind === 'generic'` | 19 | 任何过得了 `fits` 的技能 | 允许（`maxStacks` 2~3） | 每局都攒得到东西的下限 |
| **专属词条** `scope.kind === 'exclusive'` | 18（一招至少一条） | 只在指名的技能上 | **恒为 1 层** | 改变这招怎么用的招牌强化 |

专属只有一层是刻意的：允许叠层它就退化成「数值更大的普通词条」，
玩家的构筑记忆又回到「叠满锋锐」。它给的是质变——「破军」把破阵斩的削攻从 4 抬到 10，
「斩残」把重劈变成处决专家，「蔓延」把破甲咒从单体点名改成 2 格群体。

专属校验**不写在每条 `fits` 里**，由 `toDef` 统一合成进 `canApply`。抽卡池、折算、
界面问的都是同一个函数，所以「换掉技能后专属自动休眠」是免费的；
漏写一次的后果是「破军」跑到旋风斩上——那不报错，是静默失衡。

**应用顺序 = 目录数组顺序：专属在前，普通在后。** 专属用 `set*` 改写数值，
普通用 `merge*` 往上加；反过来「破军」会把刚加上的「挫锐」抹掉，两张牌只有一张算数。
同一族效果（`atkDown` / `poison` / `heal` …）在词条侧先合成好再交给引擎，
因为引擎侧对同类是「新盖旧」，直接 push 会让第二条静默失效。

**词条能改什么，取决于 `SkillSpec` 上有什么字段。** 想加新花样先给规格加**通用**字段
并在引擎实现，不要在词条里写技能特判。现有杠杆：伤害倍率 / 冷却 / 形状 /
`onCast{Self,Foe,Ally}Effects` / `lifestealRatio` / `passiveBasicAttackMulIfMoved` /
`executeBonus`（残血加伤，阈值在结算那刻才知道，所以判定在 `skillDamage` 里）/
`splashRatio`（单体技能溅到目标邻格，**只溅伤害不溅减益**——溅了控制就等于抹掉「点谁」这个决策）。

**抽卡权重**（`modRollWeight`）：稀有度以前只是卡框颜色，池子是均匀抽的。
现在按 `common 100 / rare 42 / epic 13` 加权，专属再乘 1.8（每招只有一两条，
不加权基本见不到），并随节点深度抬高 rare/epic。一屏三张**不出重复词条**，
只剩重复项时才允许。

词条按 **rosterId** 记，不按 skillId：这样卡面能指名道姓说清楚加给谁，
换技能时投入也跟着人走而不会清零（详见 `docs/玩法重设计.md` §6.6）。
换技能后不适用的词条由 `canApply` **静默休眠**，换回去即恢复，背包页会标出来。
`rollLoot` 只抽**本场上场**的人（`deployedCharacters`，看布阵格），替补不进池。
按人分组轮转，尽量凑三个不同的角色；每人的候选只来自他的**主技能**。

**只强化主技能。** 临时技能不吃词条（`unitSkillSpec`）。早先是两槽都吃的，
理由是「词条挂在人身上，这个人的技能都更强了」，破在展示上：卡面只画得下一招，
于是卡上写「惊扰蜂群 · 锋锐」而实际两招都在吃那 25%——卡面说的和结算的不是一件事。
收敛到主技能之后，卡面画的那一招就是唯一被改的那一招，不需要额外一行字解释作用范围；
投入也不再被两招分摊，主技能始终是攒词条的去处。

#### 什么技能吃什么词条

两道闸门，职责分开：

| 闸门 | 谁判 | 管什么 |
|---|---|---|
| **定位** | `SkillSpec.role`（伤害 / 控制 / 辅助），作者显式声明 | 这**类**词条该不该出现在它身上 |
| **触发** | `SkillSpec.timing`（`passive` 不走施放） | 「施放后」类词条能不能挂（`isActive`） |
| **机制** | `isAoE` / `hasHeal` / `hasFoeDebuff` 等结构谓词 | 挂上去有没有东西可改 |

输出向的七条（锋锐、汲取、溅射、处决、嗜血、不息、势不可挡）走 `isOutputSkill`，
只投给 `role === 'damage'`。控制向的（挫锐、迟滞、淬毒、顽疾）不看定位——
给毒技能加毒读得通。

只有机制闸门是不够的，这是踩过的坑：判断「是不是输出技能」曾经只有一句
`damage.kind !== 'none'`，而惊扰蜂群为了让飘字有东西可飘带了 8 点即时伤，
于是被判成伤害技能，吃到「锋锐：伤害提升 25%」，把 8 抬成 10。机制上合法，
玩家读起来荒谬。**定位是玩家读得出的东西，必须显式写，不能从字段结构反推。**

定位和触发方式**不能混成一档**：`冲锋` 的定位是伤害（它把普攻打得更狠），
被动只是它的触发方式。早先把 role 写成 `passive`，结果骑兵的默认技能和可学技能
定位对不上，路线自己跟自己打架（见《玩法重设计》§7quater.2）。

反过来收得太紧会把候选池抽干，那个角色的三选一一路发药剂。下限是每个主槽技能
至少 3 条（`skillMods.test.ts`）。当前分布：主动伤害类 11-16 条，
**冲锋 3 条卡在线上**——被动没有「施放」这个挂载点，一切挂在施放上的词条对它
都是死牌，只剩 `momentum`（蓄势，读 `passiveBasicAttackMulIfMoved`）和专属「践地」。
骑兵拿满三层后就只能出药剂，补法是给被动系加杠杆或加专属词条，不是放宽下限。

词条库现在几乎是围着伤害技能长的（控制 / 辅助定位的技能各只有 5 条可挂）。
这暂时不成问题，因为**全部角色都是伤害路线**；控制 / 辅助路线的角色上线时
必须同步扩词条库，否则那个角色一整局的三选一都很单调。

**图标分两层，扩展成本才不随章节线性涨**（规则见《美术风格圣经》§6.1）：
普通词条**一条一张** `mod_*`，它是跨技能复用的通用词汇；专属词条**十八条共用一枚徽记**
`mod_signature`，因为卡面正中已经是那一招的 40px 技能图标了，再配一张专属小图
既是同一件事说两遍，也不可能在 26px 上分清十八张。所以**新技能欠 0 张词条图标，
新普通词条欠 1 张**。两个方向都由 `skillIcons.test.ts` 钉死。

**战斗里能看见什么**：每次都生效的数值词条（锋锐、迅捷）不给额外表现——反馈就是
伤害数字本身变大。**条件触发的必须飘字**，否则玩家只看到一个更大的数字、没有
「没触发时是多少」可比，那条词条对他而言就不存在。处决走 `SkillHit.modNote`，
回放层飘在伤害上方。「要不要给稀有词条叠专属特效」的完整评估见《特效圣经》§9——
结论是不叠，画面预算和美术成本都撑不住。

加一条词条要做的事、以及「新**主槽**技能必须配专属」这条纪律，由 `skillMods.test.ts`
守着。只进临时槽的技能不要配专属词条——词条只强化主技能，那种内容连候选池都进不去。

### 临时技能槽

局内商店买到的技能进**第二个槽**（`run.runTempSkill[rosterId]`），不覆盖主技能。
两槽冷却各自独立，但**共用每回合一次的施放额度**——它加的是选项，不是出手次数，
所以不改变行动经济（`PendingTurn.castableSlots` 列出此刻放得出来的槽）。

临时技能**不挑职业**且**场景专属**：每章有自己的一套，
`ShopPoolRow.tempSkill` 只允许通用技能（由 `dungeonPool.test.ts` 守着）。

投放节奏是**每章只新增 1/2/3/4/4 招**（合计 14 招，就是现有全部临时技能）：

| 章 | 本章新增 |
|---|---|
| 1 草原 | 野草缠足 |
| 2 密林 | 松脂火把、荆棘绞缠 |
| 3 要塞 | 撞城槌、压制号令、飞爪钩索 |
| 4 毒沼 | 草药敷治、树皮庇护、攻城战旗、战场祝福（全是续航/增益——这一章的地形每回合在扣血） |
| 5 龙岭 | 牧野号角、惊扰蜂群、守林人之姿、战吼 |

原先第一章一口气开四招，那是四段要读的说明文字，出现在玩家连高地都还没用熟的时候。

**池子是「本章新增 + 上一章」的滑动窗口，不是全量累积。** 全量累积到第五章会有 14 招，
而商店一次只 roll 3 件（还保底一件药剂）——想要的那招基本抽不到，「选一个流派」
就退化成抽奖。滑动窗口让每章的池子由本章的族主导，上一章的留一轮作过渡。

**地形券也只卖已经登场过的地形**：第一章只有高地券，第二章加森林券，第三章起加城墙券。
还没见过森林就卖森林券，等于让玩家花钱买一个他读不懂的东西。

临时技能的设计口径是**主打功能不主打伤害**（`role` 为 `control` / `support`）：
它和主技能共用施放额度，如果它也是「打一发伤害」，玩家每回合就是在两个伤害技能里挑大的，
第二槽退化成一次静默的数值升级。做成控制/治疗，它才有「主技能进冷却时我还能干点别的」
这个存在理由。

**临时技能不吃词条**（见上文），所以它怎么买都变不成主力，也不必给它配专属词条——
早先给四条临时技能各写了一条（藤网 / 良方 / 蜂王 / 号令），规则收敛后它们连候选池
都进不去，已删。

### 角色技能路线

**一个角色能带的所有技能（默认 + 可学）定位必须一致**（`CharacterDef.skillRoute`，
由 `characterCatalog.test.ts` 守着）。

这条约束是拿来解一个具体矛盾的：词条按人存、按当前主技能判定生效，而主技能在布阵页
随时能免费换。三者组合的结果是「换一次主技能，攒了一路的词条批量静默休眠」。
路线内定位一致之后，换招永远在同定位内换，跨定位的批量休眠进不去，
布阵页那个切换按钮回归纯战术选择。取舍过程见《玩法重设计》§7quater.3。

它**不消除所有休眠**：雷恩从旋风斩（环形 AoE）换到重劈（单体）时「横扫」仍会休眠。
那是玩家读得懂的（「这招不是范围技」），也是 §6.6 原本设想过的可控程度。

**路线属于角色，不属于职业。** 同职业的两个角色可以是两条路线——「另一个战士，
走的是控制」是期待中的扩展方式。玩家玩的是角色，职业只是它的一个属性
（后续可在此之上做职业克制、针对某职业的效果）。

当前六个角色的路线：

| 角色 | 职业 | 路线 | 可选技能 |
|---|---|---|---|
| 雷恩 | 剑士 | damage | 旋风斩、重劈、破阵斩 |
| 希尔 | 弓手 | damage | 穿透箭、速射 |
| 格隆 | 盾卫 | damage | 震击、铁锤 |
| 岚骑 | 骑兵 | damage | 冲锋、长驱突刺、铁蹄践踏 |
| 奥莉 | 法师 | damage | 炎弹、炎环 |
| 弥尔 | 祭司 | support | 圣疗、守护祷言、战场祝福 |

约束在**运行时**也拦得住，不只靠数据表配得对：`canCharacterUseSkill(def, skillId)`
是「这个角色带不带得动这一招」的唯一判断（路线 + 职业 + 非预留），
局外装配（`equipSkill`）、布阵页轮换与战前烘焙（`effectiveOwnedSkillIds`）、
名册页的技能按钮都走它。这层是给**老存档**的：可学列表收紧后，已经存进
`ownedSkillIds` 的越界技能不会自己消失，只查 `ownedSkillIds` 会让它照样装得上，
而这种漏法不报错，只会让那个角色的词条莫名休眠。

**预留技能**（`SkillSpec.reserved`）：`破甲咒`、`盾墙震慑`、`战吼`（control）
已实现但当前没角色能学，在等对应路线的角色。`战场祝福` 已由弥尔学进主槽，
仍在二至五章的临时技能池里卖。
需要这个标记是因为「技能没主人」和「技能配错了」在数据上长得一模一样——
标出来之后，可学列表里出现预留技能是**错误**，而它们的专属词条允许存在、不算死牌。
预留只指主槽。

#### 同路线内怎么差异化

路线一致解决了「换招废掉词条」，反面风险是同定位的招被写成同一招的两个数值档。
所以差异必须落在**打法**上：形状、够得着哪里、什么时机、附带什么效果。
点谁不写进技能——玩家点谁打谁，AI 按策略回退（敌人打最低血，治疗救最低血）。
技能最多能对特定目标加效果（处决残血、对某职业额外伤害），不能替操作者选定目标。
倍率和冷却只用来在打法差异之上调味，不能充当唯一区别——玩家换招时先感知到的是
「这一招打的格子不一样」，不是「这一招高 3 点伤害」。
`characterCatalog.test.ts` 给每招算一个**不含伤害数值和冷却**的「打法指纹」，
要求同一角色的可带技能两两不同。

具体分工（改造过程见《玩法重设计》§7quinquies）：

| 职业 | 两招的分野 |
|---|---|
| 剑士 | 旋风斩群伤 / 重劈邻格点杀 / 破阵斩邻格点杀 + 削攻 |
| 弓手 | 穿透箭打成线的敌人 / 速射 3 格内点杀落单残血 |
| 盾卫 | 震击高频减速（冷却 2）/ 铁锤低频重击 + 削攻（冷却 3） |
| 骑兵 | 冲锋被动不占施放额度 / 长驱突刺够得着 2 格外 / 铁蹄践踏群伤减速 |

选单体的形状有两种够得着方式（`neighborPickFoe.reach`），文案和格子图都要区分：
`exact` 是「正好 N 格」的一圈环（长驱突刺贴脸捅不到，这是它的代价），
`within` 是「N 格内」的一整片（速射被贴脸也能射）。

**技能数是角色成长曲线上的刻度，不是要凑齐的指标**：弓手和盾卫各两招，
剑士 / 骑兵三招。希尔和格隆是 `starter`，玩家第一局就带他们上场，
那时还没搞清楚地形、克制、冷却和词条怎么互相作用——两个分得清清楚楚的选择
（打成线的一堆人 / 点掉落单的那个）正好够教会他「换招是干什么用的」，
给三四个只是加认知负担。后期角色可以更花。

两招同时是机制下限：`cycleSkillForRoster` 只剩一个技能时不显示切换按钮，
那个角色就没有战术维度了，所以 `characterCatalog.test.ts` 守着「每个角色至少两招」。
新角色要加第三招时补的是**同定位但机制不同**的技能，不是把控制技能塞回输出路线。

### 词条与技能在界面上怎么露出

同一张技能图标（`skill_<id>`）在三处复用：三选一卡片、布阵页角色详情、战斗操作条。
认同一个符号，玩家才不用每个界面重学一遍。

布阵页的角色详情是**核对本局构筑的唯一入口**，所以：技能名前挂图标，
技能格子图右边列「本局纹章」（图标 + 名称×层数 + 按层数算好的效果文字），
挂不上当前技能的纹章压暗并注明可恢复。这一段的伤害 / 冷却 / 范围格子
全部读 `effectiveSkillSpec` 的结果——面板写原始值而战斗打折算值，比不显示词条更糟。

## 三、战斗系统：托管随时切 + 扫荡

一场战斗里谁在操作是**随时可变**的，而「已经赢过的关」根本不进战斗页：

| 入口 | 谁在操作 | 何时可用 |
|---|---|---|
| 开始战斗 | 默认玩家逐个操作，战斗中随时切托管（AI 代打）并随时接手 | 始终可用 |
| 扫荡 | 无人操作：**不模拟、直接判胜** | 该节点通过过一次 + 当天还有配额 |

三件事分开了，各自只干一件：

- **托管**（`sim.setAuto(on)`）解决的是**同一局里操作密度不均**。清杂兵没有决策，
  Boss 起手要走位——逼玩家开局二选一的话，他为了那三回合的关键操作得把前面十几回合
  也一步步点完。所以开关做成双向的，切托管时手上那个单位由 AI 接着打完（不吞行动），
  切回手动时从下一个该动的单位开始由玩家操作。已结算的动作不回滚。
- **扫荡**（`canSweep` / `consumeSweep` + `GameFlow.sweepNode`）解决的是**重复劳动**。
  它不建模拟器、不进战斗页、不等图集，直接 `applyVictory`。不模拟是关键：这一关
  上次是玩家赢的，AI 代打有可能输，那对玩家就是「点了扫荡倒扣一次配额还没奖励」。
  扫荡是兑现已有结果，不是重打。
- **每日配额**（`SWEEP_ROUNDS_PER_DAY`）是刷取的唯一天花板。见下。

### 扫荡的每日配额

`sweepQuota(dungeonId) = 该副本战斗节点数 × SWEEP_ROUNDS_PER_DAY`，
消耗记在 `meta.sweepUsageByDungeonId[dungeonId] = { date, used }`，**按副本各算一份**。

三个设计选择：

- **奖励一分不少**，含整章重复通关的 `DUNGEON_REPEAT_SOUL`。削奖励防刷等于让扫荡
  变成没人点的按钮——只有一章内容时，通关后玩家的持续目标就是刷魂晶，
  堵掉它就只剩「新一局里跳过前几关」这一个用途。要限就限次数，不要限收益。
- **配额按轮给而不是定个固定数**：副本长度不一样（草原 7 场，之后每章 5 场）。
  定死一个数字必然在某章不够用，而不够用的表现特别难受——扫到第 5 关时次数耗尽，
  玩家被迫手动打完剩下两关，他刚才点扫荡就是因为不想打。按轮给保证「要么完整扫一遍，
  要么完整打一遍」，不会卡在中间。
- **跨天判定读本地日期**（`YYYY-MM-DD`），存的日期不等于今天就归零。改系统时间能刷额度，
  不防：存档就在本地，真想刷的人改存档更省事；而按这个规则处理，时钟异常
  （跨时区、夏令时）最坏只是白送额度，不会把正常玩家锁在零次上。

体力系统暂不做。做的话每场战斗（含手打）都要计费，会和「Boss 关允许反复重试」
的难度设计直接冲突——那个设计依赖的正是失败不额外收费。

### 引擎：可暂停的指令式状态机

`src/battle/engine.ts`：

- `stepTurn()` 推进一个回合边界或一个单位的完整行动。人工模式下遇到玩家单位时**不行动**，
  而是挂起 `pendingTurn` 并返回；此后 `stepTurn()` 不会跳过它，直到收到指令。
- 查询合法动作：`legalMoveCells(uid)` / `legalAttackTargets(uid)` / `skillAiming(uid)`。
  **UI 不做第二套判定**，高亮和执行读同一个函数，避免「格子亮着但点了没反应」。
- 下指令：`commandMove` / `commandUndoMove` / `commandSkill(uid, targetUid?)` /
  `commandAttack` / `commandWait`。另有不依赖行动点的 `usePotion(id)`。
- 动作额度：**每回合移动 1 次 + 技能 1 次 + 普攻 1 次**——技能和普攻可以同一回合都用。
  这是对齐 AI（`actTurn` 就是「技能 → 走位 → 技能 → 普攻」）；限制成二选一，人工输出会直接
  低自动一截，扫荡就严格优于亲手打。额度用尽后若还能撤销走位，先停一下，点待机才收尾。
  移动可 `commandUndoMove` 撤回，规则与先技能还是先走无关：**走完之后还没再出手**就能撤。
  先放技能再走错，这一步仍能回到原位；走完再放技能 / 普攻才锁死，
  否则等于看着伤害数字再改站位。出手本身不能撤。
  这条规则是否该改成二选一见 [玩法重设计.md](./玩法重设计.md) §3.5。
- `setAuto(on)`（战斗中切托管）：改 `forceAuto` 并返回**切换这一下**产生的事件。
  切到自动时当前挂起的回合由 AI 接着打完（不丢弃玩家已用掉的动作额度），
  所以有事件；切回手动只影响下一个单位，事件为空。`mode` 和 `forceAuto` 分开存：
  合成一个变量的话托管就成了单向门，没有东西记得原本该由谁操作。
- `runToEnd()`（单测 / 胜率回归）：即 `setAuto(true)` 后跑到结束。GM 跳过不走这条。
- `turnStart` 事件标记每个单位回合的开始，供顺序条定位当前行动者。

### 回放 UI

`src/view/BattlePlaybackView.ts` + `src/view/battle/manualTurnUi.ts`：

- **人工回合**：当前单位脚下金环呼吸；可走格常驻高亮，射程内敌人描边。
  点空格移动、点敌人出手；单体技能需点目标，AoE 技能直接放。
- **动作条**：固定在棋盘下方、顺序条上沿那条空带里居中排，一律是 46px 的**圆形图标钮**，不写字。
  内容为「主技能槽 / 临时技能槽 / 撤销（走过才有）/ 待机」，进入瞄准态时只剩「取消」。
  试过贴着当前单位浮动（想省掉视线来回），但小格子上按钮必然压住可走格，
  等于用看不见棋盘换视线距离；位置固定还顺带让连点几个单位时手不用重新找按钮。
- **技能钮的四态**：可释放（满色 + 呼吸光环）/ 到回合但没目标（**照常亮着**，只是不发光）/
  冷却中（压暗，右下角标剩余回合）/ 本回合已放过（压暗，右下角打勾）。
  两条规则：冷却中的槽**不隐藏**，否则玩家看不到「还有几回合能再放」，
  而这正是决定要不要保守走位的依据；点不动的钮**照样能点**，点了弹一行 toast 说明原因，
  灰按钮不给回执的话玩家只会反复戳它然后认为是 bug。
- **行动额度格**：动作条上方常驻「移动 / 技能 / 普攻」三格，三态可辨——
  可用（亮）/ 已用（打勾）/ 用不了（暗）。引擎的 `PendingTurn` 同时给 `can*` 和 `did*` 就是为了这个：
  只看 `canSkill: false` 分不清「已经放过」和「冷却中」，而这两种情况下玩家该做的事不一样。
- **顺序条**：屏幕底部（药剂栏上方），头像卡片 + **角色名**（`displayName`，不是职业名——
  一队两个剑士时职业名指不出谁该动），当前行动者金底高亮。
- **战斗中用药**：HUD 药剂按钮显示库存，点击立即生效并扣 run 库存（不占行动点，两种模式都能用）。
- **托管开关**：右上角，标签写**动词**（手动时「托管」/ 托管中「接手」）而不是当前状态——
  写「自动/手动」时玩家永远要先猜这是当前值还是切换目标；当前状态由配色表达（托管中高亮）。
  切托管时引擎当场把手上那个单位打完，事件交给回放主循环去播：
  播放者必须唯一，否则接手协程和主循环会并发播同一个单位，画面串。
- **倍速 / 跳过**：x1/x2 切换；「跳过」是 GM 调试入口，**直接判玩家胜**，不跑剩余战斗。
  以前走 `runToEnd()`，AI 代打仍可能输，调试关卡就失去意义。
  玩家想快用托管 + x2，想兑现已通关结果用扫荡。
  跳过和托管都要先 `manualUi.abortWait()`：`hide()` 只擦界面，不会解开正在等玩家输入的
  那个 `await`，只 hide 的话回放协程永远挂着，屏幕上是一张谁也不动的空战场。
- **时长预算**：回合上限 30（`MAX_BATTLE_ROUNDS`）。全程托管单场 30–60 秒；
  全程手打会到几分钟，这是为策略深度有意付的代价。

### 单位信息面板（布阵页 / 战斗页共用）

`src/view/unitInfoPanel.ts`（渲染）+ `src/view/unitInfoModel.ts`（取数）。
内容：头像 / 名称 / 定位 → 基础属性 → **当前状态**（限时增益减益，仅战斗中有）
→ 普通攻击 → 装备技能（图标 + 折算后规格 + 范围格 + 本局词条）→ 临时技能。
临时技能段**不套纹章也不列纹章**，并写明「纹章只强化主技能」——套上去面板会显示
一个战斗里不会发生的数值。

取数只有一个来源：**`effectiveUnitDef`**，即战斗结算读的同一个函数，
所以面板上的数字就是这一刻真会打出去的数字。布阵页的敌人预览走
`enemySpawnToUnitState`（从 `buildBattleUnits` 抽出来复用），预览与实战不可能算出两个数。
我方主技能取 `resolveBattleSkillIdForCharacter` 而不是 `activeSkillIdForRun`——
后者不校验职业可学性，会出现面板写 A、上场放 B。

敌方副标题写定位（「敌方 · 近战」/「首领 · 远程」）而不是兵种名：
草原杂兵 `defId` 仍是 `sword`/`bow`，写出「剑士」会漏实现细节。

打开方式：

| 位置 | 我方 | 敌方 |
|---|---|---|
| 布阵页替补席 | 卡片右上「i」 | — |
| 布阵页棋盘 | 单位右上「i」角标（整格点击是取消部署，不能被抢） | 整格可点 |
| 战斗页 | 点单位 | 点单位 |

战斗页的点击优先级：**瞄准技能目标中** → 点敌人＝选目标，不弹面板；
**能普攻到** → 点敌人＝普攻；其余情况（够不着 / 已出手 / 点自己人 / 敌方回合 /
动画播放中 / 自动战斗）一律弹面板。最后几种走 `manualTurnUi.onIdleTap`，
原本是点了没反应的死区。看面板不改变战局状态，所以两种模式都放开；
面板是点击瞬间的快照，自动战斗不会因此暂停。

> `SkillSpec.timing` 保留，但**只**给 AI 排流程用。

### 伤害公式与地形

```
伤害 = max(1, floor(atk × 克制 × 攻击方站的地形 atkMul × 目标站的地形 defMul))
```

普攻与技能走**同一套**地形规则（`computeDamage` 的 `targetPos` 为必填，技能路径见
`computeSkillHitDamage`）。技能倍率作用在 `atk` 上，之后与普攻完全同路。

地形设计契约：**一种地形只有一个动词，且必须是确定性的**（`src/data/terrainSpec.ts`）。
「一个动词」约束的是**站在上面的持续影响**（加攻 / 减伤 / 掉血）；地形之间的**转移边**
（可燃、烧尽）不算动词——它只在发生的那一刻给一次飘字和贴图变化，属于看得见的因果，
不是要背的规则。

| 地形 | 移动消耗 | 效果 | 布阵角标 |
|---|---:|---|---|
| 平原 | 1 | 无 | 无 |
| 高地 | 1 | 站此造成伤害 ×1.25 | `攻+25%` |
| 森林 | 2 | 站此受到伤害 ×0.75；**可被点燃** | `承-25%` |
| 河流 | 3 | 站此造成伤害 ×0.8 | `攻-20%` |
| 沼泽 | 2 | 每回合 -5 HP | `每回合-5` |
| 燃烧 | 1 | 每回合 -8 HP；2 回合后成焦土 | `血-8` |
| 焦土 | 1 | 无（烧完的终态，只留痕迹） | 无 |
| 城墙 | ∞ | 不可通行 + **阻挡远程视线** | 无 |
| 深渊 | ∞ | 不可通行，**不**挡视线（箭从裂谷上方过） | 无 |

四层反馈，缺一层地形就会重新变成「看不出有什么用」：

1. **布阵格角标**（`renderHelpers.createTerrainBadge`，格子 < 36px 时不画）——决定站位的时刻可读。
   只出一条，这是「一个动词」契约换来的。
2. **点格子弹地形说明卡**（`view/terrainInfoPanel.ts`）——角标放不下的东西在这里：移动消耗、
   视线遮挡、转移边。视线遮挡**只**在这里能读到，因为要塞章节整片都是城墙，每格挂角标
   会把棋盘糊成一片字。
3. **战斗中归因飘字**——攻击方地形并进招式标签（「普攻 · 高地 +25%」），目标方减伤在伤害数字下方
   飘青绿字（「森林 -25%」）。文案由引擎从 spec 现算（`damage.terrainAttackNote` /
   `terrainDefenseNote`），改数值不会和显示脱节。AoE 逐目标记录，每格地形可能不同。
   地形转移飘「燃起」/「烧尽」并当场重画那一格。
4. **地形券提示**——选中券后提示语写出放下去的实际效果。

### 动态地形（`battle/terrainDynamics.ts`）

地形在战斗中可写。三条实现约定：

- **战斗私有副本。** `createBattleSim` 内部 `cloneTerrain`。关卡的 `terrain` 是模块级共享对象，
  不拷贝就会把这一局烧掉的森林永久留在关卡数据里，且 1000 局的数值模拟会一路累积失真——
  这个 bug 不报错，只让数值悄悄偏移。视图要读实时地形走 `sim.getTerrain()`，
  传进去的那份 `terrain` 入参是开战快照。
- **用 TerrainId 转移，不叠加动态层。** 下游（寻路读 `moveCost`、伤害读 `atkMul`/`defMul`、
  轮首读 `dotPerRound`、角标文案从 spec 现算）已经全部只认一个 `TerrainId`，走转移这些管线
  一行都不用改。而且「同一格既是森林又在燃烧」本来就不是想要的语义——树烧了就不该继续给减伤。
- **计时器在运行时，不在格子里。** 格子只回答「现在是什么」。`decay` 在**地形掉血结算之后**
  tick：燃烧标 2 回合就该在 2 个轮首各烧一次人再熄，放前面会少烧一轮。

地形变化走 `terrain` 事件而不是让回放层 diff 矩阵：自动模式下 `runToEnd` 会跑完整场再逐条播，
那时地形早已是终局状态，diff 不出中间过程——而「玩家看到自己那一发火点着了哪几格」正是这个机制
的全部意义。

技能改地形挂在 `skills.commitCast`（三条施放路径唯一的「真的放出去了」判定点，和冷却同一处），
字段是 `SkillSpec.onCastTerrainEffects`。作用域取 `skillCast` 事件的 `rangeCells`，
所以**只能挂 AoE 形状**：单体点名技能的 `rangeCells` 是整个瞄准环，拿它点燃会烧掉一圈。

### 视线遮挡（`battle/sight.ts`）

远程攻击要求视线通畅（近战只打邻格，两格直接相接、中间没有格子可挡，不判）。判定用
**端点定序后的 Bresenham 直线**：

- 不用「只判同行同列」这条更简单的规则，因为它在最要紧的画面下是错的——一道横贯战场的城墙，
  隔墙对射全是斜角，简单规则下没有一发被挡，城墙看起来完全没起作用。
- 端点要先定序，否则 Bresenham 在方向相反时可能走出不同格子，出现「我打不到他、他打得到我」。
  这种不对称在战棋里是致命的，玩家会认为命中判定是随机的（`sight.test.ts` 穷举格子对钉住对称性）。

`canAttackCell` / `canAttackFrom` 的 `terrain` 是**必填**的。设成可选会让「忘了传地形」表现为
某一处静默地不判遮挡，而判定散在引擎、威胁图、界面三处——让编译器逼每个调用点交出地形，
是唯一能保证三处口径一致的办法。射线技能的命中判定和高亮范围共用 `rayCellsUntilBlocked`，
分开算会出现「高亮画到墙后面但打不到那儿的人」。

接入 LOS 后第一章不需要重调数值。把遮挡临时关掉量了一遍基线：精英关 72.5% → 开启后
10 次重复均值 73.7%，而模拟器自身的标准差实测 1.75pp（`stageSim.N` 注释里那个 1.5pp 的
二项估算是对的），也就是说这点差异读不出来。原因是当时第一章的城墙只是隘口装饰，
且遮挡对称——敌方远程同样被挡。章节重排之后第一章连城墙都没有了，这条更不成问题；
真正必须读视线的是第三章「哨塔盲角」。

数据源收敛：敌人数值走 `enemyCatalog`（按副本 `enemyScaleBase × 节点 enemyScale` 缩放），玩家角色走 `characterCatalog`（base + growth × 等级），`UNIT_DEFS` 仅作兵种原型（名称/普攻面板/默认技能）。

大厅 Shell（`GameFlow.renderShell` + `src/view/TabBar.ts`），**4 个**常驻 Tab。每个 tab 回答一个不同的问题，互不重叠：

- **未拥有角色只出现在招募页，已拥有只出现在角色页。** 角色页原来还有个「收藏」区，点一下也是花魂晶解锁——同一个操作两个入口，玩家得先猜哪个是正的，两边价格万一写歪了还会对不上。
- **背包 tab 已删**（`TabId` 从 5 个收成 4 个）。判断过程见 [玩法重设计.md](./玩法重设计.md) §9.1：这一页的空是数据模型决定的，不是 UI 没做好。

节点进度可视化：`NodeStrip`（已过/当前/未来；战斗交叉剑、补给箱、Boss 骷髅），布阵页顶部使用。

### 大厅的共用件

四页共用同一套地基，避免各页再手搓一份：

| 组件 | 位置 | 解决什么 |
|---|---|---|
| `getSafeAreaInsets()` | `src/core/safeArea.ts` | 微信胶囊与底部 home indicator 避让。原来顶栏标题会被右上角胶囊压掉尾字，tab 图标压在 home indicator 上。非微信环境与 API 早期返回全 0 时有兜底，且**不缓存兜底值** |
| `createHubHeader()` | `src/view/hubHeader.ts` | 统一顶栏（魂晶 pill + 页面标题）。原来三页各画一份、副本页干脆没有，切 tab 时同一个信息会跳位置 |
| `makeSection()` | `src/ui/Section.ts` | 带标题的不透明米白分区面板。**正文一律待在面板里**——草地是 `#CCE43C` 的高频纹理，白字直接压上去读不出来（风格圣经 §6） |

| `createModal()` | `src/ui/Modal.ts` | 角色详情弹窗：`light` 白底 + 金色标题栏 + 关闭按钮 + 内容区可滚（弹窗高度受屏幕限，内容长度由数据定） |

## 五、章节投放曲线与第一章（草原战线）

### 一条硬规矩：每章只新增 1~2 种地形，且一章一个动词

这条规矩是补出来的。原先第一章七关一次铺开高地、森林、河流、城墙四种地形加四个临时技能，
节点数 10 个——是全游戏最长的一章，而它本该是教学章。后面几章反而越来越短（8/8/7/7），
曲线是倒的：**玩家在最不懂的时候承受最大信息量，学会之后反而没有新东西。**

现在的分布（唯一来源是 `stagesMvp` 的 `CHAPTERS`，那里也抄了同一张表）：

| 章 | 关数 | 节点 | 新地形 | 这一章教的动词 | 新增临时技能 | 会出手的杂兵 |
|---|---:|---:|---|---|---:|---:|
| 1 草原战线 | 4 | 5 | 高地 | 站上去打得更疼 | 1 | 0 |
| 2 密林深处 | 5 | 7 | 森林、燃烧 | 掩体对双方都生效，而且能烧 | 2 | 1 |
| 3 要塞攻防 | 6 | 8 | 城墙、机关/闸门 | 地形挡视线，而且可以被操作 | 3 | 1 |
| 4 毒沼泥潭 | 7 | 10 | 河流、沼泽 | 走得慢、打得软、还掉血 | 4 | 2 |
| 5 龙岭绝巅 | 7 | 10 | 深渊 | 绝壁切断路线但不挡箭 | 4 | 4 |

最后一列和前面几列是同一条曲线的另一条腿：**敌人也要循序渐进**。第一章杂兵全员只普攻
（教学基线，让玩家先把三角克制和高地读明白），往后每章给一个兵位挂技能，终章四个兵位
都会出手。技能挂在**怪种**上（`stagesMvp` 的 `MookTemplate.skillId`）而不是关卡上，
所以同一只怪在这一章的每一关都是同样的威胁。八条技能的清单和设计依据在
[敌人图鉴](敌人图鉴.md) §1.5。

节点数由 `buildNodes` 从关数推出（每两场战斗插一个补给点），4/5/6/7/7 关正好对应
5/7/8/10/10 个节点——**10 是上限**，再多一局就疲劳。

两条推论：

- **一关只能用它所在章节及更早登场过的地形。** 想给第四章的图摆一堵墙可以（城墙第三章就登场了），
  想给第二章的图摆一条河不行。地形券的售卖章节同理（`dungeonCatalog` 的商店池）。
- **关卡不是按创作顺序排的，是按投放顺序排的。** 重排时要连变量名一起改
  （`c<章>_<章内第几关>`），否则文件里会出现「`c1_4` 排在第二章」这种不报错的自相矛盾。
  原第一章的「渡口之争」（河流）现在是第四章第一关，「骑兵突袭」是第二章第二关，
  「高地弓阵」是第三章第一关；原第三章的「瓮城窄道 / 双门齐落」挪到终章重考。

### 第一章：4 关，只有平原和高地

| 关 | 主题 | 教学点 |
|---|---|---|
| 1 草原哨站 | 新兵剑士 ×2，玩家侧双缓丘 | 移动 / 高地增伤（`maxDeploy` 2） |
| 2 猎手小径 | 高台弓手 + 护卫，中场一对缓丘 | 远程威胁，以及「抢丘对射」这个解法 |
| 3 前哨围剿 | **精英「百夫长·卡格」**(188HP/23ATK) + 加强弓骑侧袭 | Boss 前综合考试 |
| 4 血牙酋长 | **Boss**(241HP/20ATK, **血牙咆哮**) + 加强盾/弓护卫 | 备药 / 4 上阵位 |

原来关 2 铺了四片森林当掩体。**掩体是第二章的答案**，放在这里等于同一关抛出两个新概念，
而玩家连高地都还没用熟。现在那四格换成两块中场高地：问题（弓手站在高处打你）
和解法（你也上去）用的是同一条规则。同理，Boss 关高台两侧原来的城墙也换成了缓丘。

- **新兵变体**：第一章敌人主体用 `StageEnemySpawn.stats` 数值覆盖成弱化版（1 级首通阵容可过）；后续章节回归 `enemyCatalog` 标准数值。
- **敌方技能**：小怪默认**只普攻**（不再回退职业 `defaultSkillId`）。有技能的怪在出生点挂 `skillSkin`（见 `enemySkillCatalog`：结算复用 `SkillSpec`，展示名/图标/特效可换皮）；过渡期仍可用裸 `skillId`。第一章只有 Boss 挂了 `bloodfang_roar`→底层 `savage_roar`。
- **精英/Boss 支持**：出生点可配 `name` / `boss`（体型 ×1.3）/ `stats` / `skillSkin`（或过渡用 `skillId`）。
- **难度回归**：`src/data/__tests__/chapter1Sim.test.ts` 用真实引擎模拟首通阵容跑胜率（每配置 1000 局）——推进关 ≥85%（实测 98% / 100%）、精英关 50-95%（实测 72%）、Boss 裸打 ≤50%（实测 28%）且带 2 治疗药 ≥55%（实测 75%）。改关卡/数值后必须跑此测试，且要用 `npx vitest run --disableConsoleIntercept` 读出胜率表看**余量**。当前实测值与已知问题见 [玩法重设计.md](./玩法重设计.md) §8。
  - 章内精华累积的斜率是「每两场战斗 +1」。战斗从 6 场缩到 3 场，所以 Boss 关只攒到 1 点
    （原来是 3 点），Boss 面板是跟着这个数一起下调的——**别只改一边**。
  - 模拟走**自动**模式（`mode: 'auto'`，全程 AI），所以数字是玩家一步不操作时的下限；
    人工模式的难度目前测不到，只能靠手动过关。
- **商店保底**：`rollShop` 每次 3 件中保底 1 件药剂（Boss 前补给点必能买到续航）。

### 职业技能池

主槽只放**和角色路线同定位**的技能（见「角色技能路线」）；跨定位的招走临时槽。

| 职业 | 默认 | 可学（主槽） | 预留：等控制 / 辅助路线的角色 |
|---|---|---|---|
| 剑士 | 旋风斩(环 AoE) | 重劈(邻格点杀)、破阵斩(邻格点杀+削攻) | — |
| 弓手 | 穿透箭(射线穿透) | 速射(3 格内点杀) | 破甲咒 |
| 骑兵 | 冲锋(被动) | 长驱突刺(正好 2 格)、铁蹄践踏(AoE+减速) | — |
| 盾卫 | 震击(高频+减速) | 铁锤(重击+削攻) | 盾墙震慑 |

通用技能 `战吼`（control）、`战场祝福`（support）只在**临时槽**出售，不进任何可学列表：
它们跨定位，进主槽会让换招时词条批量休眠。

Boss 专属技能（底层如 `savage_roar`，第一章展示为「血牙咆哮」）不进商店池与可学列表，玩家不可获得。
第一章 Boss 特效走皮肤 `vfxId=bloodfang_roar`（血红犬齿冲击波），与底层通用 `roar` 图集分开。

### 战斗特效

一个技能是一份**配方**（施放 / 飞行 / 命中），登记在 `src/data/vfxCatalog.ts`。
近战通常只有命中闪光；弓手是「飞箭 + 拖尾 + 命中」，穿透箭还会沿途依次结算。
发光闪光走黑底 additive，实体弹（箭）走透明底抠图，火花和飞行路径归代码。
详见《[特效圣经](./特效圣经.md)》。

与数值有关的一处：**骑兵「冲锋」不再隐形**。这个被动是「移动后普攻 ×1.35」，之前只体现为
一个玩家无从比较的数字，等于不存在。现在 `attack` 事件带 `charged` 标记，回放层据此把招式标签
改成「冲锋」并加播速度光环——和地形加成「改了这一下的伤害就得说出来」是同一条原则。

## 5.1 无尽试炼

入口在副本页，不进冒险页章节表（`DUNGEON_DEFS`）。单独 `ENDLESS_DUNGEON`，`getDungeonDef` 认这个 id。

| 规则 | 现行 |
|---|---|
| 地图 | 复用第一章第一关地形，布阵一次，之后同图连打 |
| 波次 | 最多 10 波。人数 `2 + floor((wave-1)/2)` 封顶 6，数值每波 +15%，敌人循环剑/弓/骑/盾（第一章新兵数值） |
| 推进 | 不走 `nodeIndex`。`RunState.endless` 记 wave / carry / clearedCurrent。死人不上场 |
| 奖励 | 每波当场 +1 魂晶；打完第 10 波再 +5。非终局仍掷技能三选一。没有商店、不能扫荡 |
| 掉落 | 仅无尽开战 `enableDrops`。敌死格 35% 掉药剂；走到该格**待机**才捡，路过不捡 |
| 记录 | `meta.endlessBestFloor`，失败/离开时更新 |

实现：`src/data/endlessCatalog.ts`、`ProgressManager` 的 `applyEndlessWaveVictory` / `continueEndlessWave` / `finishEndlessRun`、`GameFlow.startEndless`。

## 5.2 第二章（密林深处）完整玩法

**5 关**，主题是「林子有两面」：森林给双方 25% 减伤，所以既是玩家的掩体也是敌人的掩体，
而它还能烧。整章反复问同一个问题——这片林子现在对谁更有利，要不要一把火烧掉它。

| 关 | 主题 | 教学点 |
|---|---|---|
| 5 藤蔓小径 | 敌人躲在林子里打 | 掩体对双方都生效（森林首次登场） |
| 6 骑兵突袭 | 双翼骑兵包抄 + 中场高地 + 两翼林子 | 集火 / 反骑兵 |
| 7 松脂林道 | 一整条松林带横断战场（铺满整行） | 穿林还是烧开 |
| 8 血牙猎长 | **精英「猎长·图伦」**(230HP/25ATK，不带技能) | Boss 前综合考试 |
| 9 血牙萨满 | **Boss**(212HP/18ATK, **燎原咒火**=点燃脚下林地) | 掩体本身是有风险的 |

「哨塔盲角」（读视线）挪到第三章——那是城墙的性质，不是森林的；
「涸河林隘」（河流）挪到第四章；「骑兵突袭」从第一章挪进来，敌人换成标准数值。
「松脂林道」原来靠两端顶墙防绕行，现在林带铺满整行：绕不开，但可以穿，也可以烧——
这件事让林子自己做比让城墙提前登场更好。

- **杂兵**：本章**专属的四只腐生植物**（藤缚茧 / 喷孢囊 / 林影豹 / 苔石像），
  数值**回到 `UNIT_DEFS` 标准值**。不写 `stats` 就是标准值，刻意不抄一份数字进关卡数据。
  剪影语法和第一章一一对应（圆滚 / 宽伞 / 横长 / 穹顶 = sword / bow / cavalry / shield），
  换的只是题材与配色——图鉴与配色推演见 [敌人图鉴](./敌人图鉴.md) §2。
- **幼体档位**：`forestYoung()` 按 `UNIT_DEFS` 现算七折面板。加它是因为一只标准杂兵的
  存在感太大——实测同一张图上加减一只整兵，胜率在 ~100% 和 ~75% 之间跳，
  中间没有档位可选。排推进关曲线缺的就是这块积木。
- **精英/Boss 外观**：仍用血牙（第一章打散的部族退入密林，叙事上接得上）。
  沿用第一章的读图规矩：野生魔物是杂兵，血牙部族是精英与 Boss。专属美术排后续专项。
- **Boss 技能**：`wild_burn`（邻格 AoE + **点燃**），皮肤「燎原咒火」。
  这是第一个由 AI 施放的改地形技能，也是把整章的动词交回给 Boss：
  玩家一直烧敌人的掩体，这一关反过来烧玩家的。
- **难度回归**：`src/data/__tests__/chapter2Sim.test.ts`。玩家状态假设按第一章通关的**实际**
  meta 收入推（第一章缩到 4 关后是 21 灵魂 → 三人 2 级），不是拍一个「3 级」。
  目标：推进关 ≥75%（实测 85% / 90% / 85%）、精英关 55-90%（实测 63%）、
  Boss 裸打 ≤45%（实测 31%）且带 2 药 ≥85%（实测 93%）。
- **精英「图伦」那一格极度敏感**，扫出来的实测值记在这里免得靠外推：
  `235/27 → 27%`（比 Boss 还难）、`235/25 → 60%`、`230/25 → ~70%`、`225/24 → 80%`。
  5 点血 + 1 点攻能动 20pp，因为这场仗输赢卡在「要不要多补一刀」这个取整断点上。
- **调这一章时的一条实测结论**：Boss 关的有效旋钮是敌方**总血量**，不是 Boss 的攻击。
  把 Boss 攻击 20→18 只让胜率从 4% 动到 6.8%，因为这场仗输在消耗赛（双方每局输出 355 对 403，
  我方总血 329 而敌方总血曾高达 531）。护卫血量高不会让 Boss 战更紧张，只会让它更长。

### 关卡编号是推导出来的，不要手写

`stagesMvp` 的 `CHAPTERS`（章 → 关卡数组）是关卡编号与章节归属的**唯一来源**：
`stage.id`、展示名「第 N 关 · 标题」、`dungeonCatalog` 的节点下标全部由它推出。

之前这三处各写一遍（`id: 13` / `name: '第 13 关 · …'` / `buildNodes([12,13,14,15,16])`），
往中间插一关就要顺手改后面每一关的两个字段加一个数组，而漏改**不报错**：
`id` 运行时没人读，下标数组错了则是某关玩不到或两章共用一关。第二章从 5 关加到 6 关
正是撞上这个，所以改成了推导。关卡蓝图现在写 `title`，不写 `id` 和序号前缀。

后来把 29 关整体重排成 4/5/6/7/7 时，这个推导是唯一让那件事可做的东西：
挪一关就是在 `CHAPTERS` 里换个位置，序号、章节归属、节点表自动跟上。
唯一需要人肉跟上的是**测试里硬写的下标**——`chapter1Sim` 曾硬写 `stageIdx 0..6`，
`unitInfoModel.test.ts` 曾硬写 `STAGES_MVP[6]`，两处都会静默指到别的章节的关卡上
（前者照样跑出一个「看起来合理」的胜率，后者报的是「读不到属性」）。现在都改成从
`battleStageIndices` / `CHAPTER_STAGE_INDICES` 派生。

## 5.3 第三章（要塞攻防）完整玩法

**6 关**，两个新地形但它们是同一件事的两半：**墙是不能动的地形，闸门是能动的墙**。

三章递进：第一章的地形只能**读**（高地），第二章可以**改写**（点火烧掉林子），
到这一章第一次有了**开关**——站上机关，下一轮闸门永久打开。
前两关先把「墙挡路、墙也挡箭」教明白（前两章的地形全都不挡视线），后四关反复问
**什么时候开门**：开门是为了进去，但开了他们也能出来，而按机关要押一个人一整回合。

| 关 | 主题 | 教学点 |
|---|---|---|
| 10 高地弓阵 | 两堵墙把战场收窄成一条中路 | 城墙首次登场：这条路不能走 |
| 11 哨塔盲角 | 横墙留三个豁口，墙后弓手看不见墙这侧 | **读视线**（全游戏第一关必须读它） |
| 12 闸门机关 | 闸门只夹中路窄道，两侧敞开 | 机关是干什么的（零成本） |
| 13 放闸 | 门后压两个狼骑，**都带「撞阵」** | 开了门**他们也出来**——先清外面再开门 |
| 14 城卫长 | **精英「血牙城卫长」**(250HP/26ATK)，机关远在侧翼 | 闸门是一个**可以选择不用**的选项 |
| 15 血牙城主 | **Boss**(210HP/24ATK，**破阵冲撞**=直线穿透) | 走廊对双方都成立 |

「高地弓阵」从第一章挪来（它教的其实是城墙）、「哨塔盲角」从第二章挪来（墙挡视线不是森林的性质）；
原来的「瓮城窄道 / 双门齐落」挪到终章用满编阵容重考——闸门是全游戏唯一「可以被操作」的地形，
值得在最后再问一次。

### 机关 / 闸门的设计约束

- **轮首触发，不是踩上就开**：`startRound` 里检查有没有存活的玩家单位站在 `lever` 上，
  有则 `openGates()`。若改成「踩上立即开」，玩家可以踩一下、撤销移动、门却已经开了——
  撤销不变量要求「移动可以无代价回滚」，而开门是不可回滚的世界状态。
- **永久开启，且一次开全场**：不做「离开机关就关」是因为那会把玩家锁在里面
  （门后的人出不来，自己也回不去）；不做「只开最近的一扇」是因为玩家无从预判哪扇算近，
  规则要能在角标和一行说明里讲完。
- **敌人不触发**：AI 不会主动去站机关。这条反过来定义了闸门的用法——
  它是捷径和优势，不是通行证。`stageIntegrity` 里有断言守着**每关不开闸门也要能打到所有敌人**，
  否则托管和扫荡会一直磨到回合上限。
- 闸门关着时**挡移动也挡视线**（`blocksSight`），开了两者都通。

### 杂兵与技能

- **敌人外观换成四兵种默认剪影**（敌方自动红 tint），不再用前两章的野生魔物：
  这一章打的是**成建制的守军**，剪影从魔物换成士兵本身就是「这里不一样了」的信号。
  叙事上接得住——血牙部族退到要塞后据城而守。填充档位 `garrisonGreen()` 同第二章幼体（七折面板），
  名字叫「新募…」。
- **临时技能组**主题是攻城：这一章新增撞城槌（直线穿透）、压制号令（削敌攻）、
  飞爪钩索（自身速）三招，池子里还留着第二章那两招作为过渡（见「临时技能槽」一节的投放表）。
- **Boss 技能** `warlord_breach`（皮肤「破阵冲撞」）是直线穿透，和玩家在这一章买的撞城槌
  同一个形状。这是整章最后一课：玩家学了一路「直线穿透吃走廊的对齐」，
  而闸门通道会把自己也排成一列。

### 难度回归与一个待解决的口径问题

`src/data/__tests__/chapter3Sim.test.ts`。实测：推进关 81-100%（要求 ≥75%）、
精英关 72%（要求 55-90%）、Boss 裸打 71%（要求 50-80%）、带 2 药 92%（要求 ≥85%）。

「闸门机关」那一关实测 99.6%，这是有意的：它要让「机关是干什么的」零成本学会，
所以代价压到最低（机关就在部署区抬脚可达的地方）。这一格不是没调，是不该调。

**Boss 的区间和前两章的 15%-45% 不是同一把尺子**，这是已知问题：
前两章按**三人**上阵量，而那两关的 `maxDeploy` 也是 4；换四人重量一遍是一章 78.0%、二章 91.3%。
「Boss 是一道墙」只在三人口径下成立。第三章按关卡实际允许的四人标定，所以区间必须重设。
详见 `docs/玩法重设计.md` §12，那里记了为什么现在不返工。

## 六、存档版本

- 当前 `META_VERSION = 3`，键 `srpg_meta_v3` / `srpg_run_v4`。
- run v4：第一章扩为 7 关后 `STAGES_MVP` 下标整体变更，v3 run 直接作废（只损失一局进度）；meta 结构不变。
- **改章节结构不升版**，因为存档里没有一处依赖 `STAGES_MVP` 的绝对下标：
  run 记的是副本内的 `nodeIndex`，关卡由运行时重建的节点表解析（`GameState` 的 `currentStage`）。
  第二章从 5 关加到 6 关、以及后来把 29 关整体重排成 4/5/6/7/7，都走这条。
  唯一的影响是 `clearedNodesByDungeonId` 记的是「通到第几个节点」这个计数，
  节点数变了之后已通关的玩家会少记（或多记）几个节点——少记的重打一次 Boss 就自愈，
  多记的等于那一章白送通关。为这个代价去作废玩家的名册和魂晶不值得。
  - 章节重排把节点数从 10/8/8/7/7 改成 5/7/8/10/10，所以**老档在第一、二章会显示已通关
    但节点条对不上**（记着 10 个节点、现在只有 5 个）。这是已知的、可自愈的错位。
- 迁移（`SaveManager.migrateLegacyIfAny`）：v1 整包档清除；v2 meta 直接升 v3（名册结构兼容）；v2/v3 run 直接丢弃。
- **同版本内新增字段走 `SaveManager.normalizeRun` 补默认值，不升版**。升版会连带作废玩家的名册和魂晶，
  为一个新数字付这个代价不值。缺失字段不补是会出事的：数值字段缺失时 `+=` 会算出 NaN，
  再一路写进 `meta.metaCurrency`，把永久货币永久毁掉。
- 精华系统删除后，`normalizeRun` 还要**反向清理**旧档里的 `pendingSoul` / `statPotions` /
  `offFieldStatByRosterId` 以及 `placements[].statBonus`。留着不清不会崩，但会让存档里
  长期躺着一份没有任何代码读的数据，下一个人读到时无从判断它是死的还是自己漏了。
