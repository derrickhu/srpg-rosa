产出 → images/bg/chapter_grassland.png（654x272，CDN 分发）
生成器：Cursor 内置 GenerateImage，aspect_ratio 16:9（实际吐 3:2）

后处理：
    python3 -c "
    from PIL import Image
    src=Image.open('<母版>.png').convert('RGB')
    W,H=src.size; h=round(W/(327/136))
    src.crop((0,150,W,150+h)).resize((654,272),Image.LANCZOS).save('images/bg/chapter_grassland.png')"
    pngquant --force --strip --quality=70-95 --speed 1 --output <同名> <同名>

裁切位置 y0=150 是挑出来的：再往上会切掉敌营帐篷的下沿，再往下会削掉望楼的旗。
换母版时重跑几个 y0 对比，别照抄这个数。

为什么是 327:136：`AdventureView` 里插图占卡片上方 `ART_RATIO`(0.4) 的高度，
卡片宽 `W-48`、高 `min(H*0.42, 340)`。这个比例接近 2.4:1，很扁。
生图模型给不了这么扁的画幅，只能出宽画幅再裁——所以 prompt 里反复强调
「重点全部放在中间横带」，上下留空是给裁刀的余量。

这也是为什么插图不能画得更高：卡片一变高，插图区就变方，而素材是 2.4:1，
cover 会从左右两边裁，望楼和敌营正好被切掉。要更高的卡片得重出更方的插图。

例外说明：战斗背景（battle_bg）明令禁止出现天空，因为它要和俯视棋盘的机位对齐。
章节卡插图是「海报」，不是棋盘，允许地平线和天空——这是有意为之，不是漏改。
