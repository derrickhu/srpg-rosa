## 0. 支配性约束：角色在屏幕上只有 40 像素高

先讲这个，因为它否决其余一切。

棋盘格边长被钳制在 **28–56px**（`src/view/boardLayout.ts:25`），单位**身体**高度固定为
**0.92 格**（`AnimatedUnit.ts` 的 `UNIT_HEIGHT_CELLS`，量的是头顶到脚、不含道具）；
杂兵再矮到 **0.7 格**（`MOOK_HEIGHT_CELLS`）——块状剪影同高会显得比人还壮，
所以一个角色在真机上实际只有 **26–52 像素高**，典型值 40 左右。战斗是自动推进的、单场 30–60 秒，玩家是"看"而不是
逐帧操作。

这意味着：脸部表情、装备细节、布料纹理、渐变——**全部看不见**。凡是需要放大才能欣赏的
设计，在这个游戏里等于不存在。所有设计决策都要按 40px 的呈现来判断，不是按 256px 母版。

## 1. 视觉识别陈述

**唯一法则：40 像素高的剪影必须同时说清三件事——敌我、职业、正在干什么。任何为了细节牺牲
这三件事的画法都是错的。**

三条支撑原则，每条都附一个判定测试，用于消解具体分歧：

| 原则 | 判定测试 |
|---|---|
| **剪影优先于细节** | 当某个细节要求缩小主体轮廓才能塞进画面时——砍掉细节，保住轮廓。武器宁可夸张放大也不能缩到看不出是什么。 |
| **明度先于色相做图底分离** | 当一个角色放到某地形上分不清时，先拉明度差（≥20），再考虑改色相。色相在 40px 下会被邻近像素混色稀释，明度不会。 |
| **一个记忆点，不是三个** | 当一个角色有多个候选特征时，只保留**一个**并把它放大到失真程度，其余全部压平。三个中等强度的特征在 40px 下会糊成一团，等于零个。 |

## 2. 色板（实测）

### 2.1 角色配色编码

每个职业占一个色相区间，这是玩家分辨兵种的**首要**依据。共用肤色 `#EEC49A`。

| 职业 | 主色 | HSL | 语义 |
|---|---|---|---|
| 剑士 | `#843C0C` | H24 S83 L28 | 深红褐，最暗最沉 |
| 弓手 | `#549C0C` | H90 S86 L33 | 叶绿，林地猎人 |
| 盾卫 | `#246CB4` | H210 S67 L42 | 钢蓝，唯一的冷色 |
| 骑兵 | `#FCB40C` | H42 S98 L52 | 金黄，**最亮**，配白马 |
| 法师 | `#0E7A7A` | H180 S79 L27 | 深青绿袍 + 尖帽 |
| 祭司 | `#F5E6C8` | H40 L90 | 乳白袍；靠明度与骑兵金分开，记忆点是大金太阳杖 |
| 共用肤色 | `#EEC49A` | H30 S71 L76 | 所有人形角色统一 |

上表是从 `src/data/anim/*.json` 的静止帧现量的（去掉近黑描边后取主导色）。前四个职业铺满
色相环的四个方位；法师走青绿、祭司走高明度乳白，各用明度或色相和已有职业错开。

**新角色定色规则**：主色必须与上表**每一个**已有职业的色相差 ≥ 25°，或明度差 ≥ 20。
两者都不满足就换色，别硬上。

敌方杂兵（第一章，实测同上）：

| 怪 | 对应 defId | 主色 | HSL | 记忆点 |
|---|---|---|---|---|
| 黏泥怪 | sword | `#24C0CC` | H184 S70 L47 | 圆滚水滴，全场唯一的青 |
| 孢子菇 | bow | `#E42418` | H4 S81 L49 | 宽伞盖 + 米白斑 |
| 血牙狼 | cavalry | `#484848` | H0 S0 L28 | 四足低伏，全场唯一的**无彩色** |
| 岩甲龟 | shield | `#A86C30` | H30 S56 L42 | 厚穹顶壳 |

血牙狼走的是**饱和度**这条轴而不是色相：低饱和的炭灰在一屏花花绿绿里本身就跳得出来，
也就不用再去色相环上抢一个位置。这条路每章最多留一只，多了就变成一片灰。

上面的色相规则**只在同一剪影类别内部严格执行**（人形对人形、魔物对魔物）。跨类别时
形状已经把话说完了，颜色只要不完全一致即可——岩甲龟 H30 L42 对剑士 H24 L28 是色相差 6、
明度差 14，两条都不满足，但一个是穹顶四足、一个是持巨剑人形，实机没有任何混淆。
反过来说，如果哪天要加一只**人形**的棕色敌兵，这条就必须重新按严格口径算。

> 早期版本这张表是深棕 / 橄榄 / 钢灰 / 陶橙，四个职业挤在低饱和的暖色区里，明度也只在
> 35–68 之间飘。那正是"人物太大众、配色沉闷"的根子：色相分不开，就只能靠细节区分，
> 而细节在 40px 下不存在。

**明度就是可通行性**。这一列不是审美，是玩法信号：亮的能走、暗的走不了或要付代价，
玩家不看图例也能猜对。改地形配色时先保这个序，再谈好不好看。

| 地形 | 主色 | HSL | 中位明度 | 玩法 |
|---|---|---|---:|---|
| 高地 high | `#E4B46C` | H36 S69 L66 | **L65** | 攻击 ×1.25 |
| 草原 plain | `#CCE43C` | H69 S76 L56 | L56 | 无消耗（不画贴图，透出背景） |
| 河流 river | `#249CFC` | H207 S97 L56 | L54 | 移动 3 点、攻击 ×0.8 |
| 城墙 wall | `#6C6C6C` | H0 S0 L42 | L42 | 不可通行、受击 ×0.5 |
| 森林 forest | `#3C8424` | H105 S57 L33 | L28 | 移动 2 点、闪避 +30% |
| 深渊 abyss | 岩缘 `#84846C` / 洞口 `#140322` | — | L26 | 不可通行 |
| 沼泽 swamp | `#545424` | H60 S40 L24 | L21 | 移动 2 点、每回合 −5 HP |
| 机关 lever | `#7B7064` | 木柄 + 灰石座 | L43 | 站上去开闸，本身零动词 |
| 闸门（关）gate_closed | `#6F6358` | 灰石框 + 木门 | L39 | 不可通行、挡视线 |
| 闸门（开）gate_open | `#7E7B77` | 同一副石框、门扇抬走 | L47 | 终态，规则等同平原 |
| 燃烧 burning | 火焰 `#F07818` / 炭树 | — | 面积 L19，信号在火 | 每回合 −8，两回合后成焦土 |
| 焦土 scorched | `#3E3326` | 灰褐炭堆 | L19 | 终态，规则等同平原 |

平原不画贴图，格子直接透出战斗背景，所以它的"主色"就是背景中央草地的实测值。
深渊的主导色是岩缘而不是洞口——按面积算岩石更多，但玩家读到的是中间那个黑洞。

**多状态地形靠「同一副骨架换材质」认亲缘，不靠另画一个新物体。**
森林 / 燃烧 / 焦土是同一簇三冠；闸门关 / 开是同一副 U 形石框。
燃烧的中位明度比沼泽还暗——像素大部分是炭，识别靠火焰的色相，所以兜底色取橙不取棕
（`terrainSpec.color`，CDN 抖动那几秒也得读成着火）。
机关不要画成紫水晶：品红键色会把紫抠掉，而且这一格的信号是「一根斜出去的柄」。

### 2.3 UI 色板

冷色调外壳 + 白，语义色只用于承载信息的元素，不做装饰。

这张表已落到代码里，见 [`src/view/mvpTheme.ts`](../src/view/mvpTheme.ts) 的 `C`。
**改配色改那个文件，不要在 View 里就地写十六进制**——上一版 UI 之所以看起来东拼西凑，
就是每个界面各写各的橙、各写各的灰。

| 角色 | 常量 | 色值 | HSL | 用途 |
|---|---|---|---|---|
| 面板底 | `C.panel` | `#465470` | H220 S23 L35 | 冷蓝灰，所有面板/弹窗 |
| 留白 | `C.paper` | `#FCFCF6` | — | 占面板 38%、按钮 70% |
| 墨色 | `C.ink` | `#1A1410` | — | 描边，与角色共用同一套线条语言 |
| 主行动 | `C.primary` | `#EEC462` | H42 S80 L65 | 金色，仅用于主 CTA |
| 次行动 | `C.secondary` | `#54708C` | H210 S25 L43 | 蓝灰 |
| 破坏性 | `C.danger` | `#D2543C` | H10 S61 L53 | 放弃副本一类 |
| 金币 | `C.gold` | `#EEC446` | H45 S83 L60 | 语义锁定，别拿去做装饰 |
| 魂晶 | `C.soul` | `#B43CE4` | H283 S76 L56 | 紫，永久 meta 货币 |
| 魂晶（深底文字） | `C.soulText` | `#D8B0FF` | H273 S100 L84 | 饱和紫在深蓝面板上读不动，文字用这档 |
| 精华 | `C.essence` | `#C4E0D2` | H149 S31 L82 | 薄荷绿 |
| 生命 | `C.hp` | `#E05446` | H5 S71 L57 | 红 |
| 不利小字（深底） | `C.warnText` | `#FF9A7A` | H14 S100 L74 | `danger` 是按钮填充色，8px 小字压在近黑底上读不出来 |

**深色底上的小字一律另开一档，不要复用按钮填充色。** 已有两处踩过：`soul` → `soulText`、
`danger` → `warnText`。按钮色是为「大色块 + 白字」调的，拿去当 8px 前景色时对比度不够。
判据很简单：字号 ≤ 10px 且压在 `C.ink` 上，就必须用提亮档。

**金币和魂晶是两种货币，图标和颜色都不许混**。金币（`icon_gold`）是单局内的，出关清空；
魂晶（`icon_soul`）是永久的，用来升级、学技能、招募、解锁章节。还有第三个容易混的
「精华」（`icon_essence`，薄荷绿），那是单局内加属性的道具，不是货币。
魂晶此前长期只有文字没有图标，玩家分不清它和金币，就是因为少了这个符号。

**金色按钮压在草地上要套一圈米白**。主 CTA 是 `#EEC462`（L66），战场草地是 `#CCE43C`
（L56），明度只差 10，光靠一圈近黑描边压不住，按钮会陷进草里。`makeButton` 给
primary / secondary / danger 三档自动加了 2px 的 `C.paper` 外圈，logo 用的是同一招。

## 3. 形状语言与比例

- **头连头发约占总高一半**，身体四肢占另一半，几乎没有脖子。理由是 40px 下头部是唯一还能
  承载识别信息的部位。**不要写 "2 头身" 或 "2.5 头身"**——弓手 v1 和第一版 lineup 都栽在
  这句上，生出来是高瘦的小人，在棋盘上细节糊成一团、人反而显小。按 1.5 头身的吉祥物来画。
- **身体近正方形，宽高比 0.9–1.0**。这是唯一可量的验收口径，量的是**身体**（头顶到脚），
  不含道具。实测现有剑士 1.01、血牙酋长 0.98（对）；弓手 v1 0.67、第一版 lineup 0.54–0.68（错）。
- **道具可以自由超出格子**：竖举的长枪、法杖、犄角、翎羽都随便画，不会被裁掉，也不会把角色
  压小。运行时归一化的是打包期 `bodySpan` 切出的身体高度，道具已被排除（见 §8 脚注）。
  这里曾经有过一条"道具不许高过头顶"的约束，已废除——那是引擎缺陷倒逼美术让步，
  代价是每个新角色的设计都要迁就它。**不要再把这条加回来。**
  道具仍应有**体量**而不只是细长，否则在 40px 下会退化成一根看不清的线。
- **简化优先于刻画**：全身 4–6 个平涂色，其中一个占据身体大部分、就是这个角色的专属色。
  不画腰带扣、口袋、铆钉、甲片缝、系带、走线、花纹、刻纹。五官只有眼睛和眉毛，最多一条嘴线，
  不画鼻子耳朵腮红。手是连指手套，不分手指。**用几笔和颜色把人说清楚，不要堆细节**——
  48px 下细节只会变成噪点，并让角色显得更小更碎。
- **近黑厚描边**：实测均值明度 **L 5–9%**、微微偏暖（剑士 `#120B0A` / 弓手 `#151007` /
  血牙酋长 `#1E1610`），其中 36–64% 的描边像素是严格纯黑。写 prompt 时
  `pure black` 和 `very dark brown` 都会落进这个区间，两种写法都可接受；**不可接受的是
  中等明度的彩色描边**（L > 15%）。
- **描边占比 28–33%**：实测占角色可见像素的 30%（剑士 29.8% / 弓手 30.0% / 血牙酋长 32.6%）。
  这是 Godot 手搭资产和 AI 生成资产之间**唯一天然一致**的东西，是整个风格的锚。低于这个数
  在草地上会糊掉。
- **平涂 + 轻 cel shading**：一个固定亮部、一个固定暗部，不要渐变、不要材质噪点、不要厚涂。
- **3/4 俯视镜头**，与棋盘视角一致。
- **武器夸张**：武器尺寸按"能在 40px 下认出类型"来定，可以违反解剖比例。

## 4. 角色美术方向

### 4.1 怎么避免"普通"

生图之前先做这三步，跳过这三步就会得到又一个通用奇幻小人：

1. **先定剪影，再定内容**。用一句话描述这个角色的外轮廓，且这句话不能套用到已有任何角色身上。
   反例："拿剑的战士"（剑士已占）。正例："驼背、单肩扛巨物，轮廓像个倾斜的三角"。
2. **选一个记忆点并放大到失真**。血牙酋长的记忆点是那把带缺口的巨大屠刀 + 牛角盔；不是
   "他很壮"。记忆点必须是**形状**，不能是颜色或材质——40px 下形状活得最久。
3. **对照已有阵容做差异检查**。新角色和 sword/bow/shield/cavalry/bloodfang 逐个比：
   色相差够不够（§2.1）、剪影会不会撞、记忆点是否重复。有一项撞了就回到第 1 步。

### 4.2 敌我区分

**第一手段是造型：敌方不是人形。** 我方是四个人形职业，敌方杂兵是魔物/野兽（黏泥怪、
孢子菇、血牙狼、岩甲龟），敌方精英与 Boss 是血牙部族兽人。扫一眼棋盘，上半场没有一个
两足小人，这件事本身就把阵营说清了，不需要读颜色。

红色 tint `0xffaaaa` 退居兜底，**只加在与我方共用美术的集合上**
（`animSets.sharesPlayerArt`，即四个 UnitKind）。有专属外观的怪一律不染：
乘法着色会把冷色洗成脏灰（黏泥怪的湖蓝首当其冲），为了一个已经不需要的区分手段
毁掉「一眼认出是谁」，不划算。

因此：

- 新敌方杂兵优先做**非人形**。要做人形（部族兵、叛军）就必须在造型上自证敌意，
  并且和四职业逐个做 §4.1 第 3 步的差异检查。
- 不要把红色作为我方角色的主色——共用美术的关卡里叠 tint 后会更难分。

Boss / 精英额外享受 **1.3 倍体型**（`BattlePlaybackView`），所以 Boss 的设计要经得起放大，
细节密度可以比杂兵略高一档，但仍受 §0 约束。

### 4.2.1 杂兵可以只有一张静止图

杂兵不必做四方向。缺图集时运行时会自己降级：没有 `walk_*` 时 `playWalk` 退回 idle
（棋子照样滑格移动），没有 `attack_*` 时退回代码突刺（朝目标冲出去再回来，260ms）。

**呼吸一律用代码做，不要出图。** 两张几乎一样的 AI 帧之间必然抖动，画出来的呼吸读成
画面在沸腾而不是生物在喘气——行走 sheet 打包成 1-2-1-4 也是为了躲这个。
`AnimatedUnit` 对没有行走图集的单位按脚线做挤压拉伸（幅度 4.5%、周期 2.3s、相位随机），
干净、零图集开销、能随时调。相位必须随机错开，一排怪同频起伏比不动还假。

代价是这类怪永远正面朝镜头。第一章可以接受；一个需要玩家判断朝向的敌人（比如背刺机制）
就必须做完整四方向。

### 4.3 已知冲突（新资产必须避开，老资产择机修）

实测发现三处色彩撞车，都会实际损害可读性：

| 冲突 | 实测 | 后果 |
|---|---|---|
| **弓手 vs 草原** | 色相差仅 33°，饱和度差仅 3 | 弓手在草地上迷彩化，只靠 18 点明度差撑着。第一章全是草原，这是当前最严重的一处。 |
| **骑兵 vs 高地** | 色相差 12°，明度差 2 | 骑兵站高地上几乎融进去。而高地是核心机制（增伤/仰攻），必看清。 |
| **剑士 vs 骑兵** | 同为 H22–23 | 两个职业靠明度（35 vs 54）勉强分开，色相编码在这里失效。 |

**规则**：新角色定色时，除了和职业色比（§2.1），还要和它常驻的地形色比，
色相差 ≥ 25° 或明度差 ≥ 20，两者至少满足一条。

## 5. 场景与地形

- 地形块是**背景**，永远不能比站在上面的单位更抢眼：地形不描黑边，单位用 30% 黑描边，
  这个反差就是图底分离的主要手段。**不要给地形加描边。**
- 地形靠**明度**分层，序见 §2.2。玩家不读图例也能猜出哪里能走。
- 地形纹理保持低频。高频细节在 40px 格子里会和单位的描边打架。
- 地形是**居中的贴纸**，不是无缝 tile：`createTerrainCell` 把贴图等比缩到格边长后居中摆放，
  相邻两格之间会露出草地，这是有意的。例外是河流和沼泽——一条横贯棋盘的河如果格格分离，
  会读成一串水坑，所以这两种在 `TERRAIN_OVERSCALE` 里放大一点让相邻格咬合。
- 战斗背景（`images/bg/battle_bg.png`）是**舞台不是主角**：中央 65% 必须是干净空草地，
  树冠只在四边镶一圈。它同时也是主页、布阵、结算的底图。
- **补给点**另用平视底图 `images/bg/shop_bg.png`：商人/摊是正视 chibi，不能套俯视棋盘底。
  补给点底允许地平线与天空（同章节卡例外）。
- 背景**俯视就要整张都是地面**，不能有天空、地平线、云。树从正上方看是圆冠，不是侧面剪影。
- 背景按 **cover** 铺满屏幕（等比放大后裁掉多出的方向），母版 2:3。机型宽高比从 0.46 到 0.56
  不等，早期是分别赋 width/height 的非等比拉伸，长屏手机上树冠会拉成椭圆。
  裁掉的只会是四边的镶边，中央空草地始终完整。

## 6. UI 视觉语言

- 冷蓝灰外壳 + 大面积白留白（面板 38%、按钮 70%）。UI 不与战场争夺注意力。
- 金色 `#EEC462` **只给主 CTA**。一屏最多一个金色按钮，否则主次失效。
- §2.3 的语义色是锁死的：金=货币、薄荷=精华、红=生命。不要拿它们做装饰性配色。
- 图标用实心剪影 + 同一套描边，不用线性图标——项目整体是厚描边平涂，线性图标会显得是外来物。
- UI 与角色**共用一个墨色描边** `C.ink`。UI 自己另配一套线条色，就会看起来像贴上去的
  另一个作品。

### 字体

全站文字走 [`docs/字体规范.md`](./字体规范.md)：正文系统字；标题/按钮/技能气泡用**得意黑**展示子集。
禁止业务手写 `fontFamily`，禁止用 emoji/符号字形当图标。

### 按钮和面板不用贴图

按钮、面板要在任意宽高下拉伸，而九宫格贴图的四角必须像素级一致——生图模型给不了这个精度。
扁平色块加粗描边这种风格，用 `PIXI.Graphics` 画反而更准、更省包体，也不占 CDN。
所以 [`src/ui/Button.ts`](../src/ui/Button.ts) 和 [`Panel.ts`](../src/ui/Panel.ts)
是**纯代码绘制**，只有 logo 这种尺寸固定、有纹样的才用生成图。

（仓库里曾经躺过三张 392×440 的 `btn_primary` / `btn_secondary` / `panel_bg` 母版，
从未被任何代码引用过，比例也和实际 7:1 的横条按钮对不上。已删。）

按钮档位用 `variant` 表达语义，**不要逐处传颜色**：

| variant | 用途 | 底 / 字 |
|---|---|---|
| `primary` | 主行动，一屏一个 | 金 `C.primary` / 深棕 |
| `secondary` | 次行动 | 蓝灰 `C.secondary` / 米白 |
| `danger` | 破坏性操作 | 红 `C.danger` / 米白 |
| `ghost` | 关闭、取消，**只用于米白面板上** | 近透明 / 深字 |

按钮底部露 3px 深色下沿，按下时面和文字整体沉进去。手机上没有 hover，这个位移是玩家
唯一拿得到的"点到了"反馈。面板反过来不做任何立体效果——它不响应交互，加了只会抢注意力。

### 图标

- 实际显示 **15~22px**，源图 64px 长边。设计时按指甲盖大小判断，不是按母版。
  节点进度条上的补给/BOSS 只有 15px，是全局最小的一档。
- 一次出全套，别分几次生：线条粗细和简化程度对不齐，摆在一行里就露馅。
- **不要用 emoji 代替图标**。emoji 字形由系统字体决定，微信真机上各家画得都不一样，
  有的机型直接渲染成方框。齿轮、三种药剂、底栏五个 tab、节点条的补给/BOSS、
  各处的锁与魂晶，以前全是 emoji，已换成图。
- 图标不是正方形（精华 39×64、部署 59×64）。统一走 `createUiIcon(key, size)` 等比缩放，
  别自己给 sprite 赋 `width = height = size`，那会把窄图标横向拉宽近一倍。
- **同一个图标可能压在两种反差极大的底色上**。底栏 tab 未选中时在 `C.panel`(#465470) 上、
  选中时在 `C.primary`(#EEC462) 上。靠「亮填充 + 近黑粗描边」两头兼顾：深底靠填充认形，
  金底靠描边认形。所以这类图标**不能用金色/浅黄做填充**，会在选中态上消失。
- **纯几何的记号不出贴图**：对勾、翻页尖角这类走 `drawCheck` / `drawChevron` 直接画。
  任意尺寸都清爽，也不用担心 `✓`、`◀` 这些字形在裁过的游戏字体子集里缺失变成豆腐块。
- **图标别铺满它所在的底**。节点圆点直径 20px，图标取 15px（直径的 3/4）——
  图标自带粗描边，铺满会把圆环盖住，而圆环颜色是「已过 / 当前 / 未到」的唯一区分。
- **空的容器读作坏掉的容器**。战斗节点没有专属图标，圈里空着会让人以为这一格没画完；
  把序号画进圈里既填满了它，又省掉圈外那行容易和「补给 / BOSS」标签混淆的数字。
- **状态差异不能只靠尺寸和颜色**。十个节点排成一排时，大 4px、亮一档在扫一眼时读不出来。
  当前节点上方额外加一个倒三角「你在这」标记，这才是唯一一眼能定位的形式。

### 6.1 技能图标与词条图标

这两套是 UI 图标里唯一会**随内容无限增长**的部分（每章都加技能、每章都加词条），
所以规则必须固化，否则每次扩内容都要重新拍一遍脑袋。

**一个技能一张图，键名 `skill_<skillId>`。** 同一张图在三处复用：三选一卡片（40px）、
布阵页角色详情、战斗操作条。认同一个符号，玩家才不用每个界面重学一遍。
加技能必须同步加图标，漏了会退成灰色占位圆，由 `skillIcons.test.ts` 守着。

**词条图标分两层，这是为了让扩展成本不随章节线性涨：**

| | 图标 | 为什么 |
|---|---|---|
| **普通词条** | 一条一张，键名 `mod_<短名>` | 它是跨技能复用的**通用词汇**，玩家一局要见几十次，必须各自可认 |
| **专属词条** | 全部共用一枚徽记 `mod_signature` | 卡面正中**已经是那一招的 40px 技能图标**了，再配一张专属小图就是同一件事说两遍 |

专属词条走徽记还有个算术上的理由：专属是**一招一条**，技能数只会越加越多，
一条一图意味着每加一个技能就欠一张 26px 上根本分不清的图。徽记 + 技能大图 +
色条上的「专属」字样三者合起来已经把「这是这一招的招牌强化」说清楚了。
**所以扩展成本是：新技能 0 张词条图标，新普通词条 1 张。**

**画的时候按这几条来：**

- 只压在**米白卡面 `#FCFCF6`** 上，不会出现在金色高亮上，所以允许暖黄和金色做填充
  （和底栏 tab 那批规则相反，别互相借用）；描边仍然必须是近黑粗描边，不然在米白上会飘。
- 显示尺寸 **16~44px**：三选一大卡 40px、背包页列表 26px、卡面右下角的类型小标签 16px、
  布阵页「本局加成」14px。按 16px 判生死——在那个尺寸上活不下来的细节一律删掉。
- **每个图标必须是一整块连通的剪影**，不要有飘在旁边的独立小部件。既是 16px 的可读性要求，
  也是切图要求：`split-tile-sheet.py` 默认按连通域分块，散件会让块数对不上名字数。
- **语义以 `src/data/skillModCatalog.ts` 为准**，改 prompt 前先对一遍。图和描述对不上时，
  玩家信的是图——他在 0.5 秒里先看到图标，文字是后到的。
- **最容易糊的是同族的两条**，必须靠**形状**而不是颜色区分：挫锐（降攻）是断裂的剑、
  迟滞（降速）是脚镣；淬毒是绿色药瓶、汲取是红心。都画成向下箭头就等于没画。
- **一次出全套**。分批生的批次之间线条粗细和简化程度对不齐，摆在一行里立刻露馅。
  实在要补第二批（现在这批就是），必须把现役图标作为**参考图**传进去，
  并在 prompt 里点名「只学画法，不要抄题材」。

现役 prompt：[`skill_mod_icons_3x3_prompt.txt`](./prompt/skill_mod_icons_3x3_prompt.txt)（第一批 9 个）、
[`skill_mod_icons_b_prompt.txt`](./prompt/skill_mod_icons_b_prompt.txt)（第二批 10 个 + 徽记）。

## 7. VFX 风格

> 完整规则、配方模型、管线见《[特效圣经](./特效圣经.md)》。这里只留视觉铁律。

- **特效服务打击感，不是换一张发光贴纸。** 一个技能是「施放 / 飞行 / 命中」的组合配方；
  远程没有飞行段，读起来就是「敌人自己爆了」。
- 发光闪光走**黑底 additive**；箭/矛等实体弹走**透明底抠图 + 普通混合**（靠剪影认是什么）。
- 闪光**不描边**。描边是角色的专利；实体弹可以有描边。
- 配色按能量分层：中心白热 → 中段主色 → 外沿深色。
- **特效配色是独立一套，不跟角色主色走。** 一个职业一族色相，普攻和技能同族、靠形态区分：

  | 职业 | 特效色族 | 白热 → 主色 → 外沿 |
  |---|---|---|
  | 剑士 | 金橙 | `#FFF6D0` → `#FFC94A` → `#FF8A1F` |
  | 弓手 | 青蓝 | `#E4FEFF` → `#5FE6FF` → `#0F9FD0` |
  | 骑兵 | 紫红 | `#FFE0F8` → `#FF5AE0` → `#A32BD0` |
  | 盾卫 | 银白 | `#FFFFFF` → `#DFE9F5` → `#9FB2C8` |

  为什么不复用 §2.1 的角色主色：弓手主色是绿，而战斗背景是亮绿草地；骑兵主色金黄和剑士撞。
- 特效主色还要避开它命中的角色主色，否则打在身上看不见。
- **火花不进生图。** 交给代码（`vfxSparks.ts`）；生图只负责大形状和实体弹剪影。

## 8. 资产标准

| 项 | 标准 |
|---|---|
| 源帧尺寸 | 256×256（`--cell-size 256`），只决定清晰度不决定屏幕大小 |
| 角色宽高比 | **身体**（头顶到脚，不含道具）**0.9–1.0**，近正方形 |
| 用色数 | 全身 4–6 个平涂色，其中一个是专属主色 |
| 屏幕站立高度 | 身体占 0.92 格，由清单 `metrics` 自动归一化，**出图时不用凑角色在帧里的占比** |
| 描边 | 近黑（L ≤ 10%），占角色可见像素 28–33% |
| 行走 | 四方向 × 4 帧（打包成 1-2-1-4，第 3 列复用第 1 列），右向由左向镜像 |
| 迈腿幅度 | 腿部剪影差异 ≥ 15%，出图时原样粘贴 `docs/prompt/_walk_motion_block.txt` |
| 攻击 | 每方向 2×2 sheet，`attack_up` 可省（回退镜像右向），但我方主力建议做齐 |
| 跨动作体型 | 打包期自动对齐到静止动作，出图时各动作占比不必自己凑齐 |
| 杂兵 | 可以只出一张正面静止图，四只一张 2x2 一次出全套；呼吸和出手位移由代码补（§4.2.1）；屏幕高度 0.7 格 |
| 头顶血条 | 底边对齐 `unitHeadLocalY`（脚线 − 身体高度）再上移 4px；禁止再写死 `cell * 0.4` |
| 图集预算 | 普通单位 ≤ 300KB，Boss ≤ 550KB，单帧杂兵 ≤ 20KB。图集走 CDN 不随包，但仍要控体积——首次进战要现拉 |
| 命名 | 见 `sprite2anim.mjs` 的 `SETS`；集合 id 我方 = `defId`（职业名），敌方专属外观用 `animSet` |
| 静态 token | 不手写，`scripts/anim2token.mjs` 从图集派生；**敌我共用一个裁剪框**，各切各的就没法比大小了 |

场景与 UI 资产的标准（不走 `generate2dsprite`，管线见 [prompt README](./prompt/README.md)）：

| 资产 | 规格 | 去向 |
|---|---|---|
| 战斗背景 | 832×1248（2:3），运行时 cover | CDN |
| 章节卡插图 | 654×272（327:136），运行时 cover + 上圆下方遮罩 | CDN |
| 地形贴图 | 长边 128px，透明底，无 plain | CDN |
| UI 图标 | 长边 64px，显示 15~22px，透明底 | **随包**（`images/ui`，约 130KB） |
| logo | 640×302，透明底 | 随包 |
| 按钮 / 面板 / 对勾 / 尖角 | 无贴图，`PIXI.Graphics` 绘制 | — |

**章节卡插图的比例是被卡片布局逼出来的**，不能随手改。插图占卡片上方 `ART_RATIO`(0.4)，
卡片宽 `W-48`、高 `min(H*0.42, 340)`，算下来接近 2.4:1，很扁。生图模型给不了这么扁的画幅，
只能出宽画幅再上下裁——所以 prompt 必须把重点全压在中间横带。反过来说，
**想把卡片做高就得重出更方的插图**：卡片一高插图区就变方，cover 会从左右两边裁，
草原章的望楼和敌营正好在两侧，会被切没。

**身体高度是怎么量出来的**：打包期 `scripts/lib/animAtlas.mjs` 的 `bodySpan` 在静止参考帧上
做距离变换——测「这里能塞进多大的圆」，头和躯干厚、刀刃再宽也薄，据此定头顶；脚线用逐行宽度
低于最宽行 25% 判定。所以**道具画多高、朝哪个方向斜，都不会把角色压小**。
细节与标定规则见[美术管线](./美术管线-AI-sprite.md#单位大小的统一标准)。

## 9. 风格禁区

以下一律不做，出现即返工：

- 写实、厚涂、笔触感、照片纹理
- 渐变填充、柔和外发光、景深模糊
- 描边缺失、描边明度 L > 15%、描边带明显彩度；给地形加描边
- 线性/描边风图标（与厚涂平涂体系冲突）
- 需要放大才能看清的细节：面部表情、装备刻纹、布料花纹
- 高瘦身形（身体宽高比 < 0.85）；prompt 里写 "2 heads tall" / "2.5 heads tall"
- 腰带扣、口袋、铆钉、甲片缝、系带、走线等碎件；鼻子、耳朵、腮红、分开的手指
- 细如线的长兵器（有高度没体量，40px 下退化成噪点）
- 角色主色落进已有职业色相 ±25° 且明度差 < 20
- 图内任何文字、标签、水印、UI 边框
- 特效使用与受击角色相近的主色
- **战斗背景**里出现天空、地平线、云，或从侧面看的树（俯视视角下整张图都该是地面）。
  章节卡插图不受此限：它是海报不是棋盘，允许地平线和天空
- 用 emoji 充当图标；线性图标；UI 自己另配一套描边色
- 拿 `✓ ◀ ▶ ▼ ★` 这类符号字形当图形用（游戏字体是裁过的子集，缺字会出豆腐块）
- 把金币、魂晶、精华的图标或颜色混用
- 在 View 里就地写十六进制配色（进 `mvpTheme.ts` 的 `C`），或给按钮逐处传颜色（用 `variant`）
